# 항공권 데일리 스캐너

Travelpayouts Data API 로 매일 항공권을 수집해 대시보드를 만든다.
GitHub Actions 가 매일 07:00 KST 에 실행하고 GitHub Pages 로 배포한다.

**청주 근처 거주자 기준으로 채점한다.** 청주(CJJ)를 홈 공항으로 두고,
인천·대구·부산을 대안 출발지로 같이 본다. 매일 네 공항 전부와 스위스를 스캔한다.

## 무엇을 보여주는가

| 탭 | 내용 |
|---|---|
| 요약 | 전체 TOP 5 · 청주 출발 TOP · 오늘의 변동 |
| 주말여행 | 주말 포함 + 연차 0~1일 조건을 만족하는 일정만 |
| 어디서 뜰까 | 같은 도시를 네 공항 중 어디서 뜨는 게 유리한지 비교 |
| 출발지별 | CJJ / ICN·GMP / TAE / PUS 별 목록 |
| 스위스 | 현재 최저가 + 특가. 5~10박 |
| 노선별 | 노선마다 지금 가격이 눌려 있는지 |
| 평균 비교 | 같은 노선·박수 안에서 현재 가격의 위치 |

## 채점 기준

DEAL SCORE 96점 만점, B등급 계수 0.85 를 곱해 실질 상한은 82점이다.

| 항목 | 배점 | 근거 |
|---|---|---|
| 할인율 | 35 | 같은 노선·박수 중앙값 대비 |
| 실부담가 | 15 | 권역 기준선 대비 절대 수준 |
| 주말 적합도 | 22 | 주말 포함 + 연차 0일 22점 / 1일 17점 / 2일 8점 |
| 접근성 | 10 | CJJ 10 · TAE 5 · PUS 4 · ICN·GMP 3 |
| 직항 | 8 | 직항 8 · 1회 환승 4 |
| 연휴 | 6 | 공휴일이 여행 구간에 걸릴 때 |

**주말여행의 정의**는 "주말(토·일) 포함 + 연차 0~1일"이다.
토·일·공휴일은 연차로 세지 않으므로, 월요일이 빨간날이면 토·일·월·화 일정도
연차 1일로 잡힌다. 평일 19시 이후 출발이면 그날은 연차로 세지 않는다 (퇴근 후 탑승).

**실가격이 항상 주 표기다.** 실부담가(= 항공권 + 청주에서 그 공항까지 왕복 교통비)는
보조 지표로만 붙는다. 인천이 5만원 싸도 리무진 왕복 4.4만원이면 실이득이
6천원이라는 것을 "어디서 뜰까" 탭에서 한 줄로 보여준다.

## 설치

**1. 레포 만들기 (공개)**

이 폴더 전체를 새 레포에 올린다.

```
scanner.py
README.md
.github/workflows/daily.yml
```

**2. 토큰 등록**

레포 → Settings → Secrets and variables → Actions → New repository secret

- Name: `TP_TOKEN`
- Secret: Travelpayouts 토큰 32자리

**토큰을 코드나 README 에 직접 쓰지 않는다.** `scanner.py` 의 `DEFAULT_TOKEN` 은
비어 있어야 한다. 공개 레포에 토큰이 올라가면 즉시 재발급해야 한다.

**3. Pages 켜기**

레포 → Settings → Pages → Source 를 **GitHub Actions** 로 설정.

**4. 첫 실행**

Actions 탭 → "항공권 데일리 스캔" → Run workflow.

성공하면 `https://<사용자명>.github.io/<레포명>/` 에서 대시보드가 열린다.

## 조정 포인트

`scanner.py` 상단 상수만 고치면 전부 반영된다.

| 상수 | 기본값 | 설명 |
|---|---|---|
| `HOME` | `"CJJ"` | 홈 공항 |
| `ACCESS_COST` | CJJ 0 / ICN 44000 / GMP 40000 / TAE 30000 / PUS 56000 | **추정치다.** 실제 이동수단·인원에 맞춰 고친다 |
| `ACCESS_SCORE` | CJJ 10 · TAE 5 · PUS 4 · ICN·GMP 3 | 돈으로 안 잡히는 이동 시간 부담 |
| `NIGHTS` | `(2,3,4,5)` | 근거리 박수 |
| `SWISS_NIGHTS` | `(4, 14)` | 유럽 체류 범위 (박) |
| `SWISS_WINDOW` | `(3, 180)` | 유럽 출발일 창. 근거리보다 훨씬 넓다 |
| `WINDOW_MIN/MAX` | 3 / 75 | 출발일 검색 창 (D+3 ~ D+75) |
| `HOLIDAYS` | 2026 하반기 | **연차 계산의 근거.** 만료되면 실행 시 경고가 뜬다 |
| `ROUTES` / `SWISS` | 17 + 3 노선 | 스캔 대상 |

호출량은 국내 17노선 × 4박수 = 68 회, 스위스 6노선 × 1 회(flex) = 6 회로
총 74 회다. `SEARCH_BUDGET` 은 130 이라 여유가 있다.

**근거리와 장거리는 수집 방식이 다르다.** 근거리는 `length` 로 박수를 못 박아
호출하고, 스위스는 `length` 를 빼고 한 번만 호출한 뒤 응답의 `return_at` 으로
실제 체류일을 계산해 5~10박만 남긴다. 장거리는 캐시가 얇아서 박수를 못 박으면
응답이 통째로 빈다 (2026-08-30 실측: length 5~10 으로 18 회 호출해 전부 0 건).

## 스케줄

`.github/workflows/daily.yml` 의 cron 은 **UTC 기준**이다.

| KST | cron (UTC) |
|---|---|
| 07:00 | `0 22 * * *` |
| 08:00 | `0 23 * * *` |
| 21:00 | `0 12 * * *` |

GitHub 의 예약 실행은 부하에 따라 **수 분에서 한 시간까지 밀릴 수 있다.**
정시 실행이 보장되지 않으므로 분 단위 정확도가 필요하면 다른 방법을 써야 한다.

## 상태 파일

`flight-deals/state/price_history.json` 이 변동추적(신규/하락/상승/소멸)과
노선별 역대 최저가(`route_lows`)의 근거다. 워크플로가 매 실행마다 레포로
커밋하므로 지우면 추적이 초기화된다. 실행을 거듭할수록 "역대 최저" 판정이
정확해진다.

**공개 레포이므로 이 파일에서 관심 노선과 가격 이력이 그대로 보인다.**

`flight-deals/state/brief.json` 은 아침 브리프용 요약이다.
`top` / `weekend` / `home_airport` / `swiss` 네 묶음을 담는다.

## 수동 실행

```
python scanner.py            # 전 출발지 + 스위스 (로테이션 없음)
python scanner.py --raw      # API 응답 구조 확인
```

`--all` 은 호환용으로 남아 있지만 기본 동작과 같다. 요일 로테이션은 폐지했다.

로컬 실행 시 토큰은 환경변수 또는 저장 파일에서 읽는다.

```
python scanner.py --save-token <토큰>
```

## 알려진 한계

- **Travelpayouts 는 캐시 데이터**다. 실시간 판매가가 아니며 등급 상한은 B다.
  예약 전 판매처에서 직접 확인해야 한다.
- **이동비용은 추정치다.** `ACCESS_COST` 는 1인 왕복 기준으로 잡은 값이라
  인원·이동수단이 다르면 실부담가가 어긋난다. 그래서 실가격을 주 표기로 둔다.
- **공휴일 표는 수동 관리다.** 검색 창(D+75)이 `HOLIDAYS` 의 마지막 날짜를
  넘어가면 그 이후 일정의 연차 계산이 부정확해진다. 실행 로그와 대시보드
  사이드바에 경고가 뜨므로 그때 갱신한다.
- `depart_date` 월 필터와 `one_way` 파라미터가 API 에서 무시된다.
  왕복 기간 통제는 `length` 가 담당하며 코드에서 박수 검증을 다시 한다.
- **스위스 캐시가 거의 없다.** 2026-08-30 실측에서 ICN→ZRH·BSL 은 원본 0 건,
  GVA 는 2 건이었다. 그래서 유럽만 검색 창을 D+180 · 4~14박으로 넓히고
  출발지를 공항코드(ICN)와 도시코드(SEL) 양쪽으로 조회한다. 그래도 비면
  대시보드에 "스위스 데이터 없음"이 그대로 표시된다 — 조회 실패가 아니라
  소스에 데이터가 없는 것이다.
- **청주(CJJ) 캐시가 얇다.** ICN 대비 6% 수준이라 결과가 비거나 표본이
  적을 수 있다. 표본 수와 기준선 단계는 카드의 `기준선(중앙값)` 줄에서 확인한다.
  기준선은 3단으로 내려간다: 노선·박수(표본 3+) → 노선 전체 박수(3+) →
  목적지 기준·출발지 혼합(5+). 아래 단으로 갈수록 비교가 거칠어진다.
- API 가 공항코드를 도시코드로 접어서 응답한다 (ICN→SEL, KIX→OSA).
  실제 편 기준으로 중복을 제거한다.
